## AES

### 简介

AES（Advanced Encryption Standard，译高级加密标准），是一款用来替代 DES 的对称加密算法，DES 当时被弃用的原因是密钥长度只有 56 位，现代的算力很容易就将其爆破出来。至于什么是对称加密算法，比如说你给我发一段话 'hello'，用 123456 当作密钥对其进行加密，然后发送给我，同样的我也要用 123456 当作密钥对密文进行解密，才能得到明文，这整个流程的加密方式就叫做对称加密。
要想了解 AES 的加密算法，我们得先知道三个概念：密钥、填充、模式。

### 密钥

密钥是对称加密的根本，对称加密之所以对称，是因为其用同一个密钥，AES 密钥的长度呢可以自己选，所以 AES128、AES192、AES256 的对应意思就是 AES 的密钥长度，密钥长度分别为 128 位、192 位、256 位。

### 填充

了解填充之前，我们还得先知道 AES 具体的加密流程。
我们用 AES128\\ECB\\NoPadding 进行举例：

1. 在加密开始之前，AES 会对数据明文以 16 byte，也就是 128 bit 进行分组，因为选用了 NoPadding ，也就是不对最后一组数据进行填充，所以每一组数据的长度必须满足长度等于 16 byte，如果最后一组长度只有 8 byte 的话会无法加密，并返回一些报错信息。
2. 分组之后利用 AES 加密器对分组后的数据明文进行加密，加密轮次包括初始轮、普通伦、最终伦，其中不同的密钥长度所对应的伦数也不一样，AES128：10轮，AES192：12轮，AES256：14轮，不同伦次的加密方式也不一样，初始轮只有加轮密钥的方式，普通伦有字节代替、行移位、列混淆、加伦密钥的方式，而最终伦只有字节代替、行移位、加伦密钥的方式，详细就不展开说了。
3. 最后将加密的密文拼接在一起。
   填充的话一般有集中选项可以选，分别是 NoPadding、PKCS5Padding、ISO10126Padding。

Nopadding 顾名思义是无填充，所以加密前的密文每一组的长度必须是 16 byte，也就是 128 Bit，不然就会报错，不给加密。

PKCS5Padding（默认），如果明文块少于 16 byte，就会在缺少的 byte 上自动填充足够相应的字符，且每个字符就等于缺少的字符数，例如 {1, 2, 3, 4, 5, 6, a, b, c, d, e} 按照一个元素一个字节来算的话，少了 16 - 10 = 6 个字节，那么如果选择的填充方式是 PKCS5Padding 的话，就会自动对缺失的字符进行填充，最后会变成 {1, 2, 3, 4, 5, 6, a, b, c, d, e, 6, 6, 6, 6, 6, 6}。

ISO10126Padding 如果明文块少于16个字节（128bit），在明文块末尾补足相应数量的字节，最后一个字符值等于缺少的字符数，其他字符填充随机数。比如明文：{1,2,3,4,5,a,b,c,d,e},缺少6个字节，则可能补全为{1,2,3,4,5,a,b,c,d,e,5,c,3,G,\$,6}

### 模式

AES 的模式有很多种，具体体现在将明文转换成密文的处理过程中，常用的模式有：ECB(默认)、CBC、CTR、CFB、OFB 模式。这里就将两个模式，ECB 模式和 CBC 模式。

ECB（Electronic Codebook Book，译电码本模式），这是最简单的模式，在这个模式中每个明文块都是独立的，互不干涉的，将明文分组后直接对其进行加密，最后拼接密文，就这么简单。其优点是支持并行运算，但因为太简单了，也有缺点，缺点就是同样的明文块会被加密成相同的密文块，安全性较差。

CBC（Cipher Block Chaining）引入了一个新概念——初始向量 IV。在这个模式中，初始明文会与 IV 进行异或（XOR），后续的每个明文块都要和**前一个明文加密后的密文快**进行异或，但这样会增加复杂度，所以这个模式的缺点就是速度相比 ECB 较慢，不支持并行计算。

### 实现

在大多数语言，比如 Java 的标准库中，我们在调用封装好的 AES 算法时，表面上使用的Key并不是真正用于AES加密解密的密钥，而是用于生成真正密钥的“种子”。同一个种子在同一个加密和解密流程下，生成的数据和解密的数据都是一样的，但如果加密和解密的 AES 包版本不一样的话，可能就解不出来数据。

## RSA

### 简介

RSA 算法是一款应用广泛的 非堆成加密算法，其存在是依靠目前因式分解难以对大数进行分解，知道公钥的情况下很难推导出私钥。RSA 的加密通式如下：
![image](https://img2.eval.moe/qexo/2026/11/718cea1baff8c6bc694620a9a86caf78.png)
其中密文是对明文进行 E 次方之后对 N 取余的结果，只要知道 E 和 N 之后任何人都可以进行 RSA 加密了，所以 E 和 N 是的组合是公钥，公钥 = （E，N）。不过 E 和 N 是通过严格的数学公式算出来的，不是很容易就得来的，E 是 Encrypt 的首字母，N 是 Number 的首字母。
解密通式如下：
![image](https://img2.eval.moe/qexo/2026/11/d1b5de4b1478138f54d0b2f03d64b729.png)
其中明文是通过对密文进行 D 次方之后对 N 取余的结果，所以私钥=（D，N）。
总结如下：


| 标题   | 字母    |
| ------ | ------- |
| 公钥   | E，N    |
| 私钥   | D，N    |
| 密钥对 | E，D，N |

### 加解密流程

首先是加密流程：

1. 取一对质数 p 和 q，这两个数通常都很大，现实一般都位 1024 位以上；
2. 算模数 n = p \* q， n 的长度就是密钥的长度，通常位 2048 位，n 是公开的；
3. 求 L = (p-1)(q-1)，L 为 p -1 和 q - 1 的最小公倍数，这个值需要保密，因为靠它能推导出私钥；
4. 选公钥指数 e：通常直接选 65537（即 0x10001）。要求是 e 与 L 互质。
5. 算私钥指数 d：求 e 关于 φ(n) 的模逆元，即满足 e × d ≡ 1 (mod φ(n))。这个用扩展欧几里得算法算。
6. 将明文转换为整数，然后利用公式进行加密
   解密流程也是套公式，这里就不细讲了。
   所以只要知道了 p 和 q 就能推导出其他的数。

### 练习

已知：p = 11，q = 17，公钥指数选 e = 7
求：
n = ?

> n = p \* q ，所以 n = 11 \* 17 = 187

L = ?

> L = (p-1)(q-1) = 160

验证 e 和 L 是否互质（即 gcd(e, L = 1)）

> 7 和 160 互质，因为它们的公因数只有 1

求私钥指数 d，满足 e × d ≡ 1 (mod L)

> d = 23，7 × 23 = 161 = 160 + 1

取明文 m = 5，求密文 c = m^e mod n

> c = 5^7 mod 187 = 146

用你算出的 d 解密，验证 c^d mod n 是否等于 5

> 146^23 mod 187 = 5
